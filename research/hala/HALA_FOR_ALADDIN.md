# Hala inside Aladdin: observed seams and proposed integration

**Source boundary:** inspected public [`TheHalfMoon/Aladdin` commit `ea801f562e56efab0714b912707d532659c89d61`](https://github.com/TheHalfMoon/Aladdin/tree/ea801f562e56efab0714b912707d532659c89d61) on 13 October 2026. This document proposes Paradigm research integration; no Aladdin code was changed. Its adopted [AI server architecture](https://github.com/TheHalfMoon/Aladdin/blob/ea801f562e56efab0714b912707d532659c89d61/docs/aladdin/ALADDIN_AI_SERVER_ARCHITECTURE.md) explicitly places Aladdin AI inference, planning, routing and speech on founder-controlled servers. Local GGUF is therefore a **possible future product variant requiring an Aladdin architecture decision**, not a drop-in current implementation. The local Core can still serve external MCP clients.

Aladdin is an authority layer with a Node MCP edge, Rust `qdrald`/policy/approval broker, Windows UIA and capture provider, computer host, and a browser worker under development. Its [architecture](https://github.com/TheHalfMoon/Aladdin/blob/ea801f562e56efab0714b912707d532659c89d61/docs/aladdin/ARCHITECTURE.md) distinguishes implemented, production-reachable, contract-only and proposed surfaces; a planning document must not be mistaken for a running AI service. The current [proposal vocabulary](https://github.com/TheHalfMoon/Aladdin/blob/ea801f562e56efab0714b912707d532659c89d61/apps/qdral-mcp/src/computer_action_proposal.ts) declares browser and coordinate verbs and explicitly forbids authority-bearing fields such as approval and policy revision. The [MCP tool contract](https://github.com/TheHalfMoon/Aladdin/blob/ea801f562e56efab0714b912707d532659c89d61/apps/qdral-mcp/src/tool_contract.ts) labels effects, approval class and remote/local exposure. [Desktop tools](https://github.com/TheHalfMoon/Aladdin/blob/ea801f562e56efab0714b912707d532659c89d61/apps/qdral-mcp/src/desktop.ts) use typed window/element identities, generation checks, one bounded action, and local Full User authority; semantic UIA is preferred to coordinate input. The browser provider's live DOM/action path is not yet production-qualified in the inspected architecture.

```text
User intent → Aladdin server planner/router → selected Hala worker
  → bounded, typed, untrusted action proposal (target reference + observation generation)
  → local qdral policy/approval/lease checks → exact MCP/desktop/browser execution
  → fresh observation + independent postcondition → continue, recover, or report unknown
```

The server should never mint local approvals, trust, target identities, leases or completion proof. The local device mints target references and enforces principal/session/device/epoch, scope, method ceiling, expiry, freshness and per-action approval. Every state mutation gets an operation ID, precondition and verifier; after timeout, inspect state before retrying. A model saying “done” has no authority as a completion receipt. Preserve Aladdin's existing failure codes and compatibility interface; any added proposal IR or relay frame needs separate versioned review.

Route by tool availability first: exact semantic UIA, browser DOM or bounded MCP call where qualified; visual Hala proposal when semantics are absent; Pro for harder reasoning and recovery. The server records screenshots only when permitted, crops exact windows, excludes protected/password surfaces, minimizes egress, and keeps raw training collection off by default. Task memory is a compact goal, latest verified state, prior actions/outcomes and bounded relevant observations; stale screenshots are explicitly invalidated. Long-running tasks need cancellation, lease expiry, resumable step records and unknown-outcome reconciliation. A disconnected server cannot relax local policy.

Security tests must cover prompt injection in page/window text, altered screenshot instructions, cross-tenant data, shell arguments, path traversal, file deletion, auth prompts, purchases, external messages and sensitive financial/government portals. Allowlists, typed schemas, device policy and explicit human approval govern effects; model refusal is an additional signal, never the only barrier. Shell/file operations remain separate Aladdin capabilities with their own policy. No real user accounts or production screenshots enter a dataset without explicit consent and asset rights. Use synthetic apps and isolated accounts for Hala experiments.

**Integration gate:** the next Aladdin-specific artifact is a versioned proposal/observation contract and a mocked end-to-end test, authored in Aladdin only after a separate implementation authorization. Paradigm can first test the same schema against synthetic traces. The proposed integration is rejected if a model can submit approval fields, bypass local typed checks, reuse stale observations, or claim success without a verifier. See [harness](HARNESS_ARCHITECTURE.md), [benchmarks](BENCHMARKS.md), and [Flash experiment](../../plans/HALA_FLASH_FIRST_EXPERIMENT.md).
