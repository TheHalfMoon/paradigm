# Hala Task Factory v 1

Reproduce Hcompany's **verifier discipline**, not its unpublished task corpus. Evidence: [Holo 4 disclosure analysis](HOLO4_DEEP_DIVE.md). Version owned tasks/environments separately from public benchmark evaluation. No web scraping or third-party accounts are necessary for the pilot.

One immutable environment image exposes noVNC for human audit, desktop screenshot/action RPC for agent, and optional browser CDP/MCP only for tasks explicitly marked to allow them. Build from licensed self-hosted apps: a mock mailbox/calendar/CRM, document editor, spreadsheet and filesystem. Use synthetic identities, local fake credentials and seeded state. Track app/license/version, container digest, OS/window manager, locale/timezone/DPI, render er/browser versions, task seed and verifier digest. A missing asset or flaky external site is an environment failure, recorded separately without quietly dropping hard tasks.

Task contract: goal, initial state hash, allowlisted tools/resources, forbidden side effects, authorized scope, expected final state predicates, time out/step limits, golden sequence, near misses, template family, split, provenance and reviewer. Completion checks inspect application/DB/filesystem deltas, not agent declarations. Verifiers may read privileged state; agents may not access the verifier/golden state. Browser-only tasks and desktop-only tasks have distinct allowed interfaces so terminal bypass cannot masquerade as GUI ability.

Four admission gates: seed fails; human golden passes; each adversarial near miss fails; a solve occurs through allowed interfaces. Test near misses such as right value/wrong row, correct draft/wrong recipient, saved wrong directory, duplicate events, partial edits, unauthorized deletion and off-by-one drag. Audit a 10%random admission sample plus all changed verifier families; quarantine ambiguous/flaky tasks. A verifier passes only after regression against its named seeds and near misses. We have designed, not executed, these environment checks.

Start 50 fresh tasks across 5 apps,10 families; multiply parameters only after splitting app/template/source families, then collect 500–2,000 successful trajectories. Reserve entire apps/template families and identities for unseen generalization; avoid task-generation prompts based on OSWorld/benchmark content. Keep disjoint development tasks for harness iteration and sealed final evaluation tasks whose text/verifiers never enter training/context. Agent-generated solutions require verifier and human audit; failure/recovery trajectories are retained, with bad actions excluded or explicitly counter labeled for later research.

Trajectory record joins observation screenshot SHA+dimensions+timestamp, compacted context, model revision, messages/tool schema digest, chosen action, coordinate map, action a ck/result, verifier state, safety events, tokens, wall time, tool time, and termination reason. Record screenshot/step alignment; an action label on a stale frame is a data defect. No hidden chain-of-thought requirement: train on authorized observable action/concise state summaries, not assumed availability or rights to another model's private reasoning.

Stage curriculum: precise click/type/drag → single-app multi-step → recovery from delayed/rendered state → cross-app work flow → long-horizon tasks with safe memory. Balance difficulty and reward specificity rather than maximize success by generating trivial templates. Stop collection if verifier false-positive rate exceeds 1%in audited sample or privacy/safety defects appear; the 1%threshold is a proposed policy, not a measured rate. Resource estimate 3–5 engineer-days initial app/image contract,5–10 verifier families and 7–15 for collection/human calibration; work depends on actual app reproducibility.
