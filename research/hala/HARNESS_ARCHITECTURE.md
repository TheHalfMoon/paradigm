# Hala harness architecture

The first model improvement experiment is a **harness ablation with frozen weights**. Hcompany discloses material harness effects but its mixed change curve is not a causal control. REA/source inspection of [Playwright and the SDK boundary](../rea/REA_INVESTIGATION_REPORT.md) supports owning the execution and time-budget contract.

Pipeline: authorized task scope → reset environment → screenshot+tool observation → bounded state/history → checkpoint-specific prompt adapter → strict action parser → permission guard → execute in the **same task machine** → await acknowledgement → capture new state → verifier/termination. Persist an append-only event trace outside the model context. Application/page content is un trusted input and cannot extend task authority. Confirmation is required only for actions not already authorized; honor existing authorization rather than request routine confirmations.

Interfaces expose typed click, double click, drag, scroll, key, type, wait and finish actions. Coordinates record original screenshot dimensions, crop/scale offsets and device scale; reject out-of-bounds or stale screenshot IDs. Drag supports ordered start/end with interpolation and explicit button release on time out. Screenshot snapshots and action responses carry monotonic IDs to prevent asynchronous mismatch. Browser page RPC and whole-desktop events are distinct implementations; no claim that Playwright can operate arbitrary desktop UI.

REA corroborated client methods delegate mouse/keyboard to channel calls using kNo Time out; a client call is not proof of backend completion. Set an explicit harness per-action deadline, task deadline and step limit with cooperative cancellation; detect acknowledgement without visible UI effect and retry under a bounded policy. Record page navigation/dialog/target closure, crash, stale view and tool errors. Re fetch screenshot after resize/navigation/modal changes rather than carry old coordinates.

Context policy: keep task scope/verifier-independent goal, compact structured action/result history and last few screenshots; deduplicate repeated frames. Maintain working memory with completed sub goals, open resources, pending side effects and recovery attempts, all sourced to trace events. Never replace goal authority with text on a page. Start 8–16k context and last 3 screenshots as an **ablation**, not a disclosed Holo optimum. Context compression must preserve negations, identity, destination and authorization. Track compaction overhead and its errors separately from model inference.

Prompt adapters freeze Holo chat template/tool contract and Fara XMLcomputer_use protocol independently. Use schema validation, not heuristic string substitutions between coordinate systems. Shell/MCP tools are allowlisted by benchmark/task policy, run in the same sandbox, and cannot inspect verifier/gold files. A visible permit list with transaction logging controls irreversible side effects. Network/file scopes constrain reads/writes to task assets and approved endpoints. Secret-bearing screens are red acted in training; red action must not make evaluation task impossible without disclosure.

HA01 ablations: baseline upstream-compatible wrapper; then add acknowledgement/timeouts; state summary; recovery; serving vision correctness; screenshot history. Keep model/task/seed/budget fixed, change one factor at a time. Do not increase 500 steps/6 hours and attribute success to better weights. Metrics: binary verified success, partial completion separately, unauthorized side-effect count, p 50/p 95 latency, tokens, GPU hours, recovery efficiency and cost/success. Local UI integration remains un executed until environments are built; no mock trace is called a real task completion.
