# Hala Flash first experiment: frozen models and harness before LoRA

**Priority:** Plume PB00/PB01 remain first for execution. This is Hala's first *future* bounded experiment; no GPU or model download is authorized or reported here. The goal is to find whether a compact model can perform useful, safe computer-use tasks at a lower complete-task cost, and whether Qwen2-VL-2B adaptation is worth training.

## Preregistered comparison

Pin the model, processor, prompt and inference server for [`Qwen/Qwen2-VL-2B-Instruct@895c3a4`](https://huggingface.co/Qwen/Qwen2-VL-2B-Instruct/tree/895c3a49bc3fa70a340399125c650a463535e71c), [`Qwen/Qwen3.5-4B@851bf6e`](https://huggingface.co/Qwen/Qwen3.5-4B/tree/851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a), [`showlab/ShowUI-2B@cabec4f`](https://huggingface.co/showlab/ShowUI-2B/tree/cabec4fcc48d15ffd3efe0b33ea9bc7d41509d60), [`microsoft/Fara1.5-4B@776a33a`](https://huggingface.co/microsoft/Fara1.5-4B/tree/776a33ae5b2ad503796a97ae20fdc66f61d2feea) for browser-only tasks, and [`Hcompany/Holo4-35B-A3B@5084587`](https://huggingface.co/Hcompany/Holo4-35B-A3B/tree/508458727831368da85d53a8055c2b0f923ed4f3) as a Pro control when compatible hardware is approved. If Holo cannot be affordably loaded, label the Pro comparison **pending**, not failed. Use each released model's native action format behind the same typed proposal adapter and the same local executor/postcondition verifier. No benchmark test trajectory enters training.

Create 120 synthetic tasks across at least six independently templated apps: 60 browser, 60 Windows desktop; at least 30 with Arabic/RTL text and 30 with unseen layout templates. Include single-action grounding, 3–8 step forms/files/settings, interruption, stale target, injected webpage instruction, no-op/ask, and recovery after a wrong click. A separate 60-task development pool can tune prompts. Seeded synthetic environments and evaluator scripts must be committed with version/hash, but keep any sensitive screenshot out of the public repo. Each test task has a deterministic final-state checker, permitted tools and effect ceiling. Seal task IDs and layout sources before seeing model outcomes; freeze prompts and max action/time budgets. Rerun stochastic tasks at least three times and cluster uncertainty by task.

Run sequential ablations with no training first:

1. Native base model + minimal screenshot/action loop.
2. Same weights + semantic UIA/DOM-first deterministic harness, bounded history, state verification and one recovery policy.
3. Qwen3.5-4B Flash alone, Holo Pro alone (when loaded), and deterministic Flash→Pro route under the same harness and budgets.
4. Only if the 2B base remains competitive and has a specific correctable grounding error: annotate 100–200 rights-cleared training screenshots from *different* apps/templates. Compare base, a single multitask LoRA and two specialized LoRAs at equal examples/steps and held-out split. Do not count resized or translated derivatives as independent samples.

Record task pass/fail and unsafe proposals, grounding target error (pixel distance and in-target rate), invalid-action and stale-state rates, recovery success, calls per completed task, screenshot bytes, p50/p95/p99 phase and complete-task latency, GPU/CPU seconds, memory peak, idle share, token/image counts, retries and dollars per *verified* success. Keep acquisition, encoding, network, queue, vision/prefill, decode, adapter switch, policy, actuation, UI settling and verification separate. Stratify by Arabic, browser/desktop, unseen app and task length. Never infer 0.2 seconds from decode-only latency.

**Decision gates:** no deployment if any unauthorized side effect or policy bypass occurs. The Flash route advances only if its paired complete-task success is within a predeclared 5 percentage-point noninferiority margin of Pro on its eligible low-risk strata, with a 95% task-cluster bootstrap lower bound above −5 points, and its complete-task cost per success is at least 30% lower; both thresholds are product hypotheses and can be revised *before* the sealed test, never after. For a 2B LoRA, require at least +5 percentage points held-out grounding accuracy over base with lower confidence bound above zero, no task-success regression and no Arabic/unseen-app regression exceeding 3 points. Stop the LoRA route after one bounded pilot if these conditions fail or memory/latency exceeds the agreed budget. If the 120-task suite is underpowered, report an interval and gather a new sealed suite rather than claim victory.

Initial preparation costs zero GPU dollars: task specs, rights audit, schema adapters and mock execution. A future smoke run needs an exact quoted GPU/CPU configuration and user-approved ceiling; a public “free T4” claim is not a reliable budget. No training starts before a load, one forward/backward/optimizer step, save/reload, VRAM and throughput report on the *actual* hardware. The Holo 70 GB BF16 weight floor makes a 16 GB T4 impossible for the Pro control without a separately validated quantized/offloaded configuration.
